## 5. 运行使用构想 ConOps

### 5.1 总体运行构想

请按以下逻辑描述：

Gateway 在国内、香港、海外部署多个 POP 节点。客户分支、门店、工厂、IoT 站点通过普通宽带、专线、4G/5G 等 Underlay 接入 Gateway POP。系统通过 IPSec/GRE Overlay 建立安全隧道，通过 BGP/OSPF/策略路由实现路由互通，通过 Geo-IP、FQDN、应用识别、SLA 探测和链路权重实现路径选择，并通过 Gateway NOC / 云运维平台提供统一可视化、告警、日志、配置和客户级服务支撑。

请生成如下 ASCII 架构图：

```text
客户分支 / 门店 / 工厂 / 电力站点
        │
普通宽带 / 专线 / 4G/5G / NAT 网络
        │
IPSec / GRE over IPSec Overlay
        │
Gateway POP 网络
        │
国内出口 / 香港出口 / 海外出口 / 客户总部 / SaaS / IoT 平台
        │
Gateway NOC / 云运维平台
```

### 5.2 场景 S1：跨境办公互联 ConOps

#### 运行参与者

* 客户总部 IT
* 分支 IT 或本地联系人
* Gateway 网络工程师
* Gateway NOC
* 终端用户
* 运营商/云服务商

#### 运行流程

```text
用户访问业务系统
    ↓
分支 CPE 识别目的地址 / FQDN / 应用
    ↓
策略引擎判断是否走 Gateway Overlay
    ↓
选择合适的 POP / Tunnel / 出口
    ↓
基于 SLA 探测持续监控链路质量
    ↓
异常时切换路径
    ↓
NOC 观察告警和链路状态
```

#### 场景 MoE

* 跨境业务可用性
* 应用体验与选路有效性
* 高可用与故障恢复
* 服务可解释性

#### 关键成功条件

* 分支可稳定接入 POP。
* 业务流可按 Geo-IP / FQDN / 应用 / SLA 进入正确路径。
* 链路异常时可切换。
* NOC 可看到链路、Tunnel、策略和告警。

---

### 5.3 场景 S2：制造业多站点互联 ConOps

#### 运行参与者

* 制造业总部 IT
* 工厂 IT 或本地弱 IT 人员
* Gateway 网络工程师
* Gateway NOC
* 业务部门用户

#### 运行流程

```text
工厂/办公室上线 CPE
    ↓
CPE 建立 IPSec/GRE Tunnel 到 Gateway POP
    ↓
BGP/OSPF 或静态/策略路由导入站点网段
    ↓
总部、工厂、海外节点间实现互通
    ↓
文件同步、ERP、办公系统走策略路径
    ↓
NOC 监控链路质量和业务路径
```

#### 场景 MoE

* 跨境业务可用性
* 应用体验与选路有效性
* 第三方现网兼容性
* 集中运维效率

#### 关键成功条件

* 不强依赖客户 LAN 改造。
* 可兼容客户存量防火墙、交换机、路由器。
* 跨站点访问路径可控。
* 异常时 Gateway 可远程定位。

---

### 5.4 场景 S3：连锁门店快速接入 ConOps

#### 运行参与者

* 连锁总部 IT
* 门店店长 / 弱 IT 人员
* Gateway 交付工程师
* Gateway NOC
* 终端用户 / 门店业务系统

#### 运行流程

```text
门店收到预配置 CPE
    ↓
门店接入宽带 / 4G / 5G
    ↓
CPE 自动上线并注册到云平台
    ↓
系统下发门店模板配置
    ↓
建立 Overlay Tunnel
    ↓
POS / 视频巡店 / 业务同步接入总部或云业务
    ↓
NOC 监控设备在线、链路质量和告警
```

#### 场景 MoE

* 分支低门槛上线
* 集中运维效率
* 高可用与故障恢复
* 成本效率

#### 关键成功条件

* 门店无需公网 IP。
* 门店无需专业 IT。
* 支持批量配置和模板复用。
* 设备异常、链路异常、质量异常可远程发现。
* 单站点成本适合中端连锁客户。

### 5.5 场景 S4：电力/光伏/IoT 站点接入 ConOps

#### 运行参与者

* 电力/能源客户运维团队
* 站点本地维护人员
* Gateway 网络工程师
* Gateway NOC
* IoT 平台 / 监控平台

#### 运行流程

```text
电力/光伏站点部署 CPE
    ↓
CPE 接入专线 / 4G / 5G / 内网链路
    ↓
站点 IoT 数据通过 CPE 汇聚
    ↓
通过 Gateway Overlay 或电力内网回传到中心平台
    ↓
NOC 监控站点在线、链路质量、设备告警
    ↓
异常时远程定位链路、设备或运营商问题
```

#### 场景 MoE

* 跨境/跨域业务可用性
* 高可用与故障恢复
* 集中运维效率
* 安全治理可支撑性

#### 关键成功条件

* 支持专线、4G/5G、内网等混合接入。
* 支持无人值守场景的远程可视化。
* 支持链路异常告警。
* 对内网/非公网场景需保留私有化或内网部署可能性，但不要默认作为 L1 基础需求。

### 5.6 场景 S5：MSP 多客户运营 ConOps

#### 运行参与者

* Gateway 管理层
* Gateway NOC
* Gateway 网络工程师
* 安全治理/SOC
* 多个企业客户 IT
* 第三方设备厂商 / 运营商 / 云服务商

#### 运行流程

```text
Gateway 创建客户租户 / 项目
    ↓
纳管客户分支 CPE 和 POP 接入
    ↓
按客户建立 Overlay / VRF / 策略模板
    ↓
统一下发配置与访问策略
    ↓
NOC 按客户查看拓扑、链路、Tunnel、告警、日志
    ↓
客户故障触发告警与工单处理
    ↓
Gateway 输出客户级服务质量和运维报告
```

#### 场景 MoE

* 多客户可运营性
* 集中运维效率
* 安全治理可支撑性
* 服务可解释性
* 成本效率

#### 关键成功条件

* 客户间资源隔离。
* 客户间路由隔离。
* 客户间权限隔离。
* 支持客户级视图和告警。
* 支持第三方设备共存。
* 支持 NOC/API 对接。
* 支持配置留痕和基础审计。

## 11. 建议的一句话收口

佳慧 Gateway SD-WAN 场景的本质，是以多 POP 跨境网络为骨干、以 IPSec/GRE/BGP 为 Overlay、以 Geo-IP/FQDN/应用/SLA 为调度、以云可视化、多租户、基础安全治理和 NOC 运营为服务底座的中端 MSP 网络服务系统；其需求开发应从利益相关者、MoE 和运行使用构想出发，而不是从单设备功能或我方产品阶段出发。
